# 界面与样式铁律

> 展开自 `AGENTS.md` 的「界面与样式」。**动任何页面 / 组件 / 样式之前先读这份。**
> 完整的设计令牌与组件清单见 [`../03-ui-system.md`](../03-ui-system.md)。

## 1. 先找同类，再动手

- 🔴 做页面 / 按钮 / 弹窗 / 浮层 / 设置项之前，先在项目里找到**同类元素**
  （同一个面板、同一种操作、同一个位置）看它怎么写的，照它的结构与类名来。
- 不要凭手感另起一套 —— **风格不统一比写错功能更显眼**。

## 2. 优先复用已有类

- 🔴 项目里已有一批公共样式类，例如 `.chip` / `.toggle-switch` / `.setting-row` /
  `.comfy-select` / `.image-slot-btn`。新元素先看能不能直接用现成的，再考虑写新样式。

## 3. 同层级必须一致

- 🔴 **同层级的元素，位置、尺寸、样式必须一致。** 例如图片槽底部的「生成 / 重试 / 放弃」
  应当是同一行、同一个对齐方式、同一套按钮样式（`.image-slot-btn`，主操作用 `.primary`）；
  不要一个居中一个靠右、一个实底一个描边。

## 4. 字号 / 圆角 / 颜色跟着邻居走

- 🔴 用 `calc(12px * var(--ui-font-scale))`、`var(--radius-*)` 这类令牌，
  不要写死像素值，也不要另调一套配色。

## 5. 别拿全局公共类名做局部样式

- ⚠️ `.modal-overlay` / `.modal-content` / `.modal-body` 是一套公共模态框系统，
  内容区带不透明实色底 —— 新组件复用这些类名会被它的背景盖住，
  还会波及用到同一套类的其它弹窗。需要自己的样式就用专属类名。

## 6. 改完直接给用户看

- 不要自己截图反复复查（判据在用户眼睛里）。允许为定位 bug 做单次针对性探测。
