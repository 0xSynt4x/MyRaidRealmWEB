# 代码、搜索与工具

> 展开自 `AGENTS.md` 的「项目上下文」「临时文件与工作目录」「搜索与阅读」「代码与架构」「工具使用」「子 Agent」。

## 1. 项目上下文

- 🔴 **本仓是自包含的独立网页应用**（通用模拟经营 / 叙事模拟平台，题材不限；`1980s` 只是仓库代号）。
  全部能力都在本仓的网页源码、运行时与 standalone 资产里实现，**不依赖任何外部工具或外部运行时**。
- 遇到陌生模块、跨模块修改或需要理解数据流时，**先读 `spec/README.md` 的索引表定位**，
  再打开对应细则，最后读实际代码。不要默认通读 `spec/`。
- 文档用于快速建立项目地图；**实际代码是最终依据**。文档与代码不一致时以代码为准，
  并在影响当前任务时顺手把文档改回来。
- 保持项目已有的架构原则、状态所有权与数据流语义。除非当前任务明确要求，
  不主动替换架构或做大规模重构。
- 这是**单项目**（一个自包含的浏览器端产物），上下文相对稳定。
  优先在当前仓库内完成工作，不主动扩展到外部资料、无关模块或后续优化。
- 以正确完成当前目标为第一优先级，同时减少无效搜索、重复读取、重复推理、无关修改和过度验证。
- 不为了省 token、省时间或少改几行而牺牲正确性、架构一致性或数据安全。

## 2. 搜索与阅读

- 开始修改前，先定位最可能相关的入口、符号、调用链和数据结构。
- 代码知识图谱与运行时数据流可做速查，见 `.workbuddy-ai/memory/cgc.md` 与 `docs/runtime-workflow.md`。
- 🔴 **搜索「先窄后宽」**：优先搜明确的函数名、类型、路径、错误信息、调用点；
  只有现有证据不足时才扩大范围。
- 已有足够证据能安全实施时，**停止搜索并进入修改**。
- 不为「完整理解项目」扫描整个仓库；不重复读取内容未变、上下文仍足够的文件。
- 大文件优先搜索目标符号并只读局部上下文，不默认整文件读取。
- 独立的搜索 / 读取 / 查询**尽量批量执行**，避免大量连续的小型工具调用。
- 不收集不会改变当前实现决策的信息。

## 3. 代码与架构

- 修改前快速理解相关模块的现有模式、类型、调用关系与状态所有权，并保持一致。
- 优先**最小必要改动**：能够正确解决问题且保持架构一致的最小改动。
  不要为了减少改动行数而复制逻辑、绕过已有抽象或制造技术债。
- 避免与当前任务无关的重构、清理、格式化、抽象升级、依赖替换或风格调整。
- 涉及构建产物、状态同步、存档、提示词链路、变量更新时，
  **保留现有的作用域守卫、快照与竞态防护语义**。
- 不修改与当前任务无关的用户代码，即使发现可以顺手优化。
- 临时文件、调试代码和一次性脚本用完立即清理。

## 4. 临时文件与工作目录

- 🔴 **临时脚本、截图、探测产物默认写项目 `Temp/`。** 该目录已被 `.gitignore` 忽略、
  被 `eslint.config.mjs` 的 `ignores` 排除，是约定好的临时落盘位置。
- 🔴 **可复用的工具脚本写 `tools/`，不要写 `Temp/`。** 判据：
  **换个参数 / 换个目标还能再用 = 工具**，放 `tools/`；
  **只验证过某一次具体改动 = 一次性产物**，留 `Temp/`。
  `tools/` 与 `Temp/` 一样已被 `.gitignore` 忽略（仅本地保留，不随仓库公开）。
  工具里的相对路径（`dist/`、`Temp/` 这类）**一律以项目根为基准**，即**从项目根运行**。
  技能目录里已有的同类脚本（`web-release-preflight/scripts/`、`cloudflare-pages-deploy/scripts/` 等）
  直接复用技能里的，不再往 `tools/` 里抄一份。
- **唯一例外**：无头浏览器 / 单文件探测这类必须走系统临时目录的场景
  （如 `C:\Users\<用户>\AppData\Local\Temp`）。这类文件**用完立即删除**，
  不在系统临时目录留下自定义命名的目录或脚本。
- 不把项目产物、生成中间物长期堆在系统临时目录 —— 系统不会自动清理它们，会一直占着磁盘。

## 5. 工具使用

- 搜索文件内容优先用专门的搜索工具，不要用 shell 的 `find` / `grep` 代替。
- 命令输出只取当前判断所需范围，避免无目的输出大型日志、完整文件、完整 diff 或整个目录树。
- 工具已经给出足够信息时，不用另一个工具重复获取同样信息。
- 工具调用失败时先按错误信息修正调用，不机械重复同一命令。
- 独立命令尽量并行执行；有依赖关系的命令串行执行。

## 6. 子 Agent

- 简单任务、单一调用链任务、强共享状态任务由当前 Agent 直接完成。
- 只有任务能真正独立拆分，且并行能明显省时或降低主 Agent 上下文负担时才用子 Agent。
- 不为「多一个视角」、重复验证或简单文件搜索启动子 Agent。
- 委派前明确范围、必要输入、预期输出和完成标准；子 Agent 只处理被委派的范围。
- 主 Agent 负责整合结果、解决冲突，并只对最终实现做必要验证。
