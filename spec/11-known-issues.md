# 11 · 已知坑与待修

> 本文件只列**当前基线**下确认存在的问题、必须守住的约束，以及有意为之的设计取舍。
> 修掉一条就删一条，别在这里堆历史。

## 待修

| 位置                                          | 情况                                                                                                                                                                                                                                                                                                                                      |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/components/setup/pages/SettingsPage.vue` | **API 没配齐时点「开始游戏」只弹一行内联提示，控制台没有任何日志，容易被当成「点了没反应」。** `validateApiConfig()` 要求主 API 的地址 + 模型，**且至少配一个辅助 API**（两边都不校验 key）；不满足时它只设内联 error，`startGame()` 直接 return。实测对照：配齐后走完流程一切正常——**校验逻辑本身没坏，是失败路径缺一条可读的日志/提示** |
| `src/i18n/index.ts` 的 `header.resetGame`     | **入口命名与实际行为不符，容易被误读成「会清存档」。** 这个入口实际做的是「回到首页」——只清当前这局的运行时数据（会话 + 消息 + 统计变量），**存档保留**。但文案是「重置游戏」，读起来像是会把存档一起清掉。**待改文案（如「回到首页」），代码暂不动**                                                                                     |

**附带发现（同一区域，暂未处理）**：一次开局里会先后建出两个 session——选预设时 `App.vue` 的 watch 先建一个，点「开始游戏」时 `createStandaloneRuntimeBaseline` 又新建一个（id 变了），前者会留下孤儿 key `th1980s:selected-preset:<旧id>`。

## 必须守住的约束（不是待修，别顺手改）

- 全局变量垫片（`src/standalone-globals.ts`）必须保持是 `src/index.ts` 的**第一个 import**。
  顺序错会在初始化阶段就炸，且报错信息不指向真正原因。
- 通知容器必须挂在 `App.vue` 根节点，否则开局向导阶段弹不出提示。

## 设计取舍（有意为之，不是缺陷）

- **测试脚本不纳入类型检查。** `scripts/tests/run-standalone-local-content-tests.ts` 不在
  `tsconfig.json` 的 `include` 里，且跑的时候是「只转译、不检查类型」模式。实测把它纳进去会冒出
  44 条报错，绝大多数是测试写法问题（不写类型、临时拼对象、把 store 属性收窄成 `null`）而非真 bug。
  CI 每次都实跑测试，所以「跑起来会崩」的错误已被拦住；漏掉的只有「编译期才发现、运行时不报错」
  那一类（典型是重复函数实现）——历史上真踩过，当前基线里没有。

  🔴 **但这条防线有个前提：测试真的跑了。** 外部 PR（fork 来的）的 CI 要维护者批准才执行，
  没批准时**一行都没跑**，本地也可能没跑 —— 此时「靠实跑兜底」等于不存在，
  接口误用类错误（公开函数改签名后调用方漏改）会一路漏到运行时。
  详见 `10-workflow-and-verification.md` 的「静态检查的两个盲区」。

- **i18n 有意保留一处中文值。** `declaration.freeSub` 的英文词条里「类脑」是频道名（专有名词），
  不翻译。`pnpm check:i18n` 因此报 **1 条 WARN**，属预期，不是待修。
- **分发只有「整目录部署到线上」一条路。** 没有 GitHub Release / 下载 HTML 到本地玩的通道，
  `dist/index.html` 引用了同级 `assets/`（30 个文件）与 `preset-package/`，脱离它们打不开完整游戏。

## 检查盲区

- 仓库 `format:check` 现在**全绿**。`.prettierignore` 排除了三类非代码资产：
  `src/assets/standalone-worldbooks/`（EJS 模板世界书 —— 格式化会重排模板内 JS 代码，实测一个文件改 683 行）、
  `src/presets/ws/*.json` 与 `src/诸界穿越预设.json`（手工维护的玩家预设数据）、
  `.github/ISSUE_TEMPLATE/`（内容表单）。
  **新增这类内容文件时要同步补进 ignore**，否则 `format:check` 会被它们带失败。
