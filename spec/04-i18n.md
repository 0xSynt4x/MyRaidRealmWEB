# 04 · 国际化

## 位置与结构

**全部在一个文件里：`src/i18n/index.ts`**（约 3100 行）。没有语言包目录，没有懒加载。

里面有**三张结构不同的词条表**，每张表各有 `'zh-CN'` 与 `en` 两个块：

| 表                    | 用途                              | 值的形态                 |
| --------------------- | --------------------------------- | ------------------------ |
| `messages`            | 普通界面文案                      | 纯字符串                 |
| `enumDisplayMessages` | 枚举值显示名                      | 嵌套对象                 |
| `fieldMessages`       | 字段的 label / placeholder / help | `{ label, placeholder }` |

- `Locale = 'zh-CN' | 'en'`，默认 `'zh-CN'`。
- 缺失的 key **会回退显示中文**——所以漏翻译不会报错，只会静默显示中文。

## API

| 函数                                                | 用途                                |
| --------------------------------------------------- | ----------------------------------- |
| `translate(locale, key, params)`                    | 按指定语言取词                      |
| `tCurrent(key, params)`                             | 按当前语言取词（组件里最常用）      |
| `translateEnumDisplay(...)`                         | 取枚举显示名                        |
| `translateField(locale, fieldPath, kind, fallback)` | 取字段的 label / placeholder / help |
| `syncDocumentLocale(locale)`                        | 同步到 `<html lang>`，切语言时调用  |
| `useI18n()`                                         | 组合式封装                          |

启动时 `src/index.ts` 会先从 localStorage 的设置里读 `locale` 并同步一次，避免首屏语言闪烁。

## 改语言文件后必跑

```bash
pnpm check:i18n
```

`scripts/i18n/check-i18n.cjs` 查三件事：

1. 三张表的**中英 key 是否一一对应**；
2. 英文块里有没有**值仍然是中文**的条目（key 对但没翻，一样显示中文）；
3. 中英条目的 **`{占位符}` 是否一一对应**（翻译时最容易丢）。

退出码：全过 0，有问题 1，可以直接挂 CI。
详细报告（含中文原文）写到 **`Temp/i18n-report.txt`**——控制台只打 ASCII 摘要，
因为本机 bash 打中文会乱码，**别靠控制台看内容**。

## 实现上的两个坑（改脚本时注意）

- 校验脚本按「行 + 块区间」扫描，而不是把文件解析成对象：文件里三张表结构完全不同，
  值可能是单引号也可能是双引号，逐行取 key 最稳且不依赖类型。
- 文件里有**三对** `'zh-CN': {` / `en: {`，必须按出现顺序成对切块。
  用 `lastIndexOf` 会锚到最后一对，把内容插错表。

## 约定

1. 新增界面文案**中英两边同时补**，不要只加中文。
2. 组件里不要拼字符串再查表；`{占位符}` 走 `params` 传参。
3. 语言文件改完必跑 `pnpm check:i18n`。
